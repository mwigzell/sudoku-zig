## What to build

Row/Col/Box lenses over flat `[81]Cell` storage, nested under `Board`. View types carry `[9]usize` indices into flat storage; resolution happens by passing a `Board.BoardView` at call time — zero-copy iteration over live cells.

### Why now (after bitmask works)

The Board has flat storage (15.1), bitmask cache (15.2). But the only read path is `getCellValue(row, col)` and `assembleRenderSnapshot` (which copies 81 cells). A solver or constraint checker needs to iterate rows, columns, and boxes efficiently — not cell-by-cell. Borrowed views fill that gap without allocating.

### Design notes

- **BoardView** is nested as `Board.BoardView`, hold-only (`*const Board`). No separate mutable variant. Replaces the current top-level `BoardView` type (already present from 15.2, but moved into Board here).
- **RowView, ColView, BoxView** are nested as `Board.RowView`, `Board.ColView`, `Board.BoxView` — plain data carrying `[9]usize indices` + identity fields computed at construction time.
- All view types are plain data (resolution method takes a `BoardView`). Board provides factory functions: `board.asRow(n)`, `board.asCol(n)`, `board.asBox(br, bc)` returning the respective nested types.
- **No Box struct owned on Grid** — the old Grid/Box types become obsolete after this + 15.5 removal.
- Views are intentionally dumb: they carry no state about what they look at beyond their index map. This keeps them cheap to copy, embed inline, and pass between call layers.

## Proposed Code (signatures only)

### Board.BoardView — read-only borrowed lens (moved from top-level into Board)

```zig
pub const BoardView = struct {
    board: *const Board,

    pub fn get(self: BoardView, row: u4, col: u4) CellValue,       // value at coordinates
    pub fn isGiven(self: BoardView, row: u4, col: u4) bool,        // given flag at coordinates
    pub fn resolve(self: BoardView, indices: []const usize) [9]CellValue, // bulk resolve against flat storage by index list
    };

```

### Board.RowView — horizontal row lens

```zig
pub const RowView = struct {

    fn getValues(self: Board.RowView, view: BoardView) [9]CellValue, // resolve through a Board.BoardView
```

## Proposed Tests (names + mechanics)

Each test is written TDD-style, red→green, co-located in `board.zig`.

### Test 1 — `"Board: BoardView.resolve() resolves same values as getCellValue"`
Verify the core read seam through Board.BoardView — both point and bulk resolve paths. Tests value resolution (`resolve` with an index list), single-cell `get(row,col)`, and `isGiven(row,col)` consistency against `Board.isGiven`.

### Test 2 — `"Board: asRow produces contiguous indices for row n"`
Verify RowView index layout (contiguous, base = `n * CELL_COUNT`) and value resolution through `getValues(Board.BoardView)`. Uses known placed values to confirm the resolved slice matches board state at that row.

### Test 3 — `"Board: asCol produces strided indices for column n"`
Verify ColView index layout (stride = `CELL_COUNT`, offset = column index) and value resolution through `getValues(Board.BoardView)`. Tests across multiple rows to exercise the stride pattern.

### Test 4 — `"Board: asBox(0, 1) produces correct scattered indices for top-middle box"`
Verify BoxView index map for a non-corner box (scatters across rows 0-2 × cols 3-5). Confirm identity fields (`boxRow`, `boxCol`), the exact `[9]usize` index set, and value resolution through `getValues(Board.BoardView)`. This is the hardest view type since indices aren't contiguous or uniformly strided.

### Test 5 — `"Board: BoardView reflects mutation on reborrow"`
Verify that a fresh `asView()` after mutations (`setCell`, `clearCell`) sees updated values and given flags. Confirms the borrowed lens pattern keeps in sync with live board state.
