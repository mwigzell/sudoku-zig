## What to build
AsciiRenderer replacing StdoutRenderer. Drop `RenderCell`, `RenderSnapshot`, and `assembleRenderSnapshot`. Renderer takes an injected writer at construction — renders from BoardView directly, no snapshot copy.

### Why now (after views are in place)

Board has flat storage + lenses (15.1-15.3). The render path still copies 81 cells into an owned `RenderSnapshot` just to iterate them row-by-row — the exact same pattern BoardView replaces for every other read path. AsciiRenderer iterates RowViews through BoardView, writes line-by-line to an injected Writer (stdout in production, memory buffer in tests), and eliminates the snapshot indirection entirely.

### Design notes

- **AsciiRenderer replaces StdoutRenderer.** No OutputSink abstraction — Writer is injected at init time. Tests wire a memory buffer; production wires stdout writer.
- **render() takes BoardView.** Signature becomes `pub fn render(self: *@This(), view: board.BoardView) !void`. Renders directly from the borrowed lens — no snapshot copy.
- **No RenderCell / RenderSnapshot / assembleRenderSnapshot in AsciiRenderer.** Those types stay in place for now (15.5 removes). AsciiRenderer reads Cell values directly from BoardView (`view.board.cells[idx]`).
- **Writer type captured at construction.** AsciiRenderer stores `*std.Io.Writer` — no comptime parameterization. Free-function calls throughout (`std.Io.Writer.writeAll(self.writer, ...)`). The caller passes the `.writer` field from a buffered writer (e.g. `&aw.writer` from an `Io.Writer.Allocating`) to get the base `*Io.Writer`. Method-style duck-typing (``.writeAll()``) does not work with this API — it requires exactly `*Io.Writer`.

### Proposed Code (signatures only)

#### columnHeader()

Copied unchanged from StdoutRenderer. Returns the column label line: `"   A B C | D E F | G H I \n"` with two leading spaces, single-space padding between letters, box dividers at column boundaries, and a trailing newline. Pure helper — no dependencies.


#### horizBorder()

Copied unchanged from StdoutRenderer. Returns the horizontal box-border line: `" +-------+-------+-------+\n"` with plus signs at box boundaries and seven dashes per box. Pure helper — no dependencies.


#### AsciiRenderer — writer-injected renderer from BoardView

**AsciiRenderer** replaces StdoutRenderer. Writer is injected at init time — tests wire an in-memory buffer via `Io.Writer.Allocating`; production wires stdout writer the same way.

`render()` takes `Board.BoardView` and renders directly from the borrowed lens — no snapshot copy. Iterates rows 0–9, building each data row via internal `cellRow(row, view, buf)` that reads cell values through `view.board.cells[idx]` and formats via `cell.displayChar()`. Border lines inserted after header and after rows 2/5.

Stores `*std.Io.Writer` directly — no comptime type parameterization. The caller resolves the concrete writer at wiring time by passing `&writer` from an `Io.Writer.Allocating` (or any vtable-backed buffered writer).

Existing public seam (`Cell.charOf`, `cell.displayChar`, `Board.asView()`) — all unchanged. AsciiRenderer uses them, adds nothing new to Board.

## Proposed Tests (names + mechanics)
Each test is TDD-style, red→green, co-located in ascii_renderer.zig. All rendering exercises the real code path: Writer writes exact strings that are compared after.

### Test 1 — `"column header"`
Keep existing pure-function test. `columnHeader()` returns exact expected string. Already passes.

### Test 2 — `"horizontal border"`
Same. Pure helper `horizBorder()`, no rendering involved. Already passes.


### Test 3 — `"cell row (empty)"`
Build an empty board (`Board.init()`), create BoardView via `asView()`. Call the internal `cellRow(0, view, &buf)` helper with a stack buffer to render just row index 0. Assert buffer equals `"1|       |       |       |\n"` (row label `1`, all cells empty).

### Test 4 — `"cell row (digits placed)"`

Build a board with some givens via `fromFlat` (row 7 has digits placed). Create BoardView. Call `cellRow()`. Extract the data row for index 7 (line 8 in output, label `8`). Assert buffer equals expected row string with digit values shown.

### Test 5 — `"AsciiRenderer renders empty board end-to-end"`

Use `Io.Writer.Allocating.init(allocator)` as Writer sink. Register AsciiRenderer with `&aw.writer`, render the board, read back via `aw.writer.buffered()`. Assert full output matches expected ASCII grid (column header + 4 borders + 9 labeled rows all spaces).
