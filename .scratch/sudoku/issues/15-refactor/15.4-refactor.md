## What to build
AsciiRenderer replacing StdoutRenderer. Drop `RenderCell`, `RenderSnapshot`, and `assembleRenderSnapshot`. Renderer takes an injected writer at construction — renders from BoardView directly, no snapshot copy.

### Why now (after views are in place)

Board has flat storage + lenses (15.1-15.3). The render path still copies 81 cells into an owned `RenderSnapshot` just to iterate them row-by-row — the exact same pattern BoardView replaces for every other read path. AsciiRenderer iterates RowViews through BoardView, writes line-by-line to an injected Writer (stdout in production, memory buffer in tests), and eliminates the snapshot indirection entirely.

### Design notes

- **AsciiRenderer replaces StdoutRenderer.** No OutputSink abstraction — Writer is injected at init time. Production wires stdout writer; tests wire a memory buffer. Other renderers (Tui, Wasm) won't need Writers at all; that separation was the whole point of dropping `StdoutRenderer` naming.
- **render() takes BoardView.** Signature becomes `pub fn render(self: *@This(), view: board.BoardView) !void`. The engine's job is to produce the borrowed lens and hand it through. This makes GameEngine and MockRenderer both satisfy the same contract without knowing about writers or sinks.
- **No RenderCell / RenderSnapshot / assembleRenderSnapshot.** Those types are dead after 15.3 views exist. AsciiRenderer reads Cell values directly from BoardView (`view.board.cells[idx]`).
- **render(row, view)** — helper on AsciiRenderer formats one data row given a row index and the BoardView, delegates `cell.displayChar()` and `Cell.charOf()` for display characters. Row formatting lives in std_renderer.zig alongside column header and horizontal border helpers.
- **GameEngine.render() changes from snapshot to view.** Produces `self.board.asView()` per-call (no allocation) instead of `assembleRenderSnapshot()`.
- **MockRenderer stores BoardView instead of RenderSnapshot.** Tests query through the stored view. Since both board and mock live on stack in test scope, the borrowed pointer is valid for the test lifetime — this validates the contract end-to-end.
- **render.zig becomes empty** once RenderCell/RenderSnapshot are dropped (nothing else uses it). Removal happens alongside this slice.
- **Writer type captured at construction.** AsciiRenderer stores the writer returned by `init(writer)` — comptime-polymorphic via `anytype` field (each instantiation locks in the concrete Writer type at compile time). Production creates stdout writer inline (`std.Io.File.stdout().writer(init.io, \&.\{\})`). Tests use `std.Io.Writer.fixed(&buf)` on a stack array — no heap allocs, no IoSink, no OutputSink union.

### Proposed Code (signatures only)

#### AsciiRenderer — writer-injected renderer from BoardView

```zig
// replaces StdoutRenderer in std_renderer.zig
pub const AsciiRenderer = struct {
    writer: anytype, // captured Writer type at init

    /// Takes the injected writer — production wires stdout, tests wire memory buffer.
    pub fn init(writer: anytype) @This(),

    /// Render the board view as ASCII grid to the injected writer.
    pub fn render(self: *@This(), view: board.BoardView) !void,
};

// Pure helpers (unchanged from StdoutRenderer)
pub fn columnHeader() []const u8,
pub fn horizBorder() []const u8,

// New helper — format one data row directly from BoardView cells
fn renderRow(self: *AsciiRenderer, rowNum: usize, view: board.BoardView) !void,
```

#### GameEngine.render() — snapshot → view

```zig
// before (std_renderer.zig / game_engine.zig)
const snap = self.board.assembleRenderSnapshot();
try self.renderer.render(snap);

// after
fn render(self: *@This()) !void {
    const view = self.board.asView();
    try self.renderer.render(view);
}
```

#### MockRenderer — store BoardView instead of snapshot

```zig
// before
last_snapshot: ?renderer.RenderSnapshot,
... mock.last_snapshot.cells[row][col] ...

// after  
last_view: ?board.BoardView,
... mock.last_view.?.get(row, col) ...
```

#### main.zig — wire AsciiRenderer directly (no IoSink, no defer close)

```zig
// before (main.zig)
var real_sink = io_sink.IoSink.initStdout(init.io);
defer real_sink.deinit(std.heap.page_allocator);
var r = std_renderer.StdoutRenderer.init(.{ .file = &real_sink });
...

// after — inline stdout writer, no defer close (stdout is process-owned)
const stdout_w = std.Io.File.stdout().writer(init.io, &.{});
var r = AsciiRenderer.init(stdout_w);
var engine = try game_engine.GameEngine(AsciiRenderer(*anyerror!void)).init(puzzle_gen.PuzzleGen.easy(), &r);
```

#### board.zig — drop dead code

```zig
- const renderer = @import("renderer.zig"),   // no longer needed
```

Existing public seam (`Cell.charOf`, `cell.displayChar`, `Board.asView()`, views asRow/asCol/asBox) — all unchanged. AsciiRenderer uses them, adds nothing new to Board.

## Proposed Tests (names + mechanics)

Each test is TDD-style, red→green, co-located in std_renderer.zig. All rendering exercises the real code path: Writer writes exact strings that are compared after.

### Test 1 — `"column header"`
Keep existing pure-function test. columnHeader() returns exact expected string. No change needed beyond renaming file context (now std_renderer instead of renderer). Already passes.

### Test 2 — `"horizontal border"`
Same. Pure helper, no rendering involved. Already passes.


### Test 3 — `"renderRow produces empty row 1 with label"`

Use `std.Io.Writer.fixed(&buf)` on a stack `[2048]u8` array as Writer sink. Build an empty board (Board.init()), create BoardView via asView(). Call AsciiRenderer.renderRow(0, view) on the writer. Assert buffer from tested helpers.

### Test 4 — `"renderRow produces row with placed values"`
Build a board with some givens via fromFlat (row 7: `.. .|4 1 9|...`). Create BoardView. Call renderRow(7, view). Assert buffer equals `"8|     4 | 1 9   |     |\n"`.


### Test 5 — `"AsciiRenderer renders empty board end-to-end"`
Use `std.Io.Writer.fixed(&buf)` on a stack array as Writer sink. Board.init() → all zeros. AsciiRenderer.render(view). Assert full output matches expected ASCII grid: column header + 4 borders + 9 labeled rows (all spaces)

### Test 6 — `"AsciiRenderer renders easy puzzle end-to-end"`
Load board via fromOneLineString(puzzle_gen.PuzzleGen.easy()). Render through AsciiRenderer to memory buffer. Compare full buffer against known-good output (the exact ASCII grid already proven correct by current zig build run). This is the production render path exercised in-memory — identical formatting, only destination differs.

### GameEngine / MockRenderer tests (in game_engine.zig)

Both existing tests updated: `"GameEngine fill updates cell in view after render"` and `"GameEngine init builds board, explicit render emits view"`. Same test assertions but query through mock.last_view.get(row,col) instead of last_snapshot.cells[row][col]. Validates the Renderer contract round-trip.
